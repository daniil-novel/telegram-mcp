# Подключение Telegram MCP к ChatGPT web

[English](chatgpt-tunnel.md) · **Русский** · [Основная инструкция](../README.ru.md)

Для ChatGPT web рекомендуем официальный [Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels). Он подключает локальный MCP через исходящее HTTPS-соединение. Домен, публичный сервер и входящий порт не нужны. Для Codex на этом же компьютере достаточно обычного локального плагина со stdio.

Клиент туннеля требует отдельный ключ даже при наличии подписки ChatGPT. Ключ авторизует соединение с сервисом туннелей. Сам мост не делает запросов к моделям через API. Для локального подключения Codex ключ OpenAI не нужен.

1. Установите Telegram MCP по основной инструкции. Самостоятельно войдите в Telegram в своём терминале. Проверьте чтение через локальный MCP.
2. Откройте [Tunnels](https://platform.openai.com/settings/organization/tunnels) в своей организации OpenAI. Создайте личный туннель, выберите нужную рабочую область ChatGPT и скопируйте `tunnel_id`. Это идентификатор, а не секретный ключ.
3. Скачайте официальный [tunnel-client](https://github.com/openai/tunnel-client/releases/latest) для своей ОС. Проверьте контрольную сумму релиза. Посмотрите справку установленной версии: `tunnel-client help quickstart`.
4. Создайте отдельный ключ для работы туннеля в [Platform settings](https://platform.openai.com/settings/organization/api-keys). Владельцу ключа нужны права **Tunnels Read + Use**. Для создания и изменения туннелей нужны отдельные права **Read + Manage**. Не передавайте клиенту административный ключ. Вводите ключ локально. Не вставляйте его в чат, репозиторий, аргументы запуска или историю команд.
5. Передайте ключ через локальное хранилище секретов в переменную `CONTROL_PLANE_API_KEY`. Создайте профиль stdio, указав настоящий ID и локальные пути:

```text
tunnel-client init --sample sample_mcp_stdio_local --profile telegram --tunnel-id <TUNNEL_ID> --mcp-command "<PYTHON> -m telegram_readonly_mcp --env-file <LOCAL_ENV_FILE> serve"
tunnel-client doctor --profile telegram --explain
tunnel-client run --profile telegram
```

Значения в угловых скобках нужно заменить. Пути с пробелами заключайте в кавычки. Локальный файл запуска может задать несекретные флаги отправки. Credentials остаются в защищённой локальной конфигурации. По умолчанию сервер только читает; [отправка](../README.ru.md#7-включение-записи) включается отдельно.

Для работы в фоне используйте `tunnel-client runtimes connect --alias telegram --tunnel-id <TUNNEL_ID> --mcp-command "<MCP_COMMAND>" --runtime-api-key env:CONTROL_PLANE_API_KEY`. Затем выполните `tunnel-client runtimes status telegram --json`. Проверьте признаки running, healthy и ready. Сохранённый профиль ещё не означает, что соединение работает. При отличиях в параметрах посмотрите справку своей версии.

6. Пока клиент работает, откройте [плагины ChatGPT](https://chatgpt.com/plugins), выберите **Добавить пользовательский сервер MCP**, затем **Туннель** и введите его ID. Для локального stdio укажите **Без аутентификации** в настройке самого сервера. Доступ защищён личным туннелем. Установите плагин в нужной личной рабочей области.
7. Сверьте список инструментов перед обращением к переписке. В режиме чтения должны быть семь инструментов и ни одного действия записи. В [навыках ChatGPT](https://chatgpt.com/skills) загрузите ZIP с [папкой навыка Telegram](../skills/telegram/) на верхнем уровне. Для работы в чате выберите и плагин, и навык, если клиент предлагает такой выбор.

Подключение относится к выбранному аккаунту и рабочей области. Оно не копирует локальный плагин или навык во все аккаунты, рабочие области и устройства. После обновления локального плагина перезапустите существующие чаты Codex.

Для вызовов должны работать компьютер и клиент туннеля. Фоновый запуск не позволяет выключить компьютер. При необходимости отдельно настройте запуск при входе в ОС. Сервер не отвечает на входящие сообщения самостоятельно и не подписывается на события переписки. Если вместо stdio используется HTTP, сохраните аутентификацию backend: не публикуйте порт и не отключайте защиту ради подключения.

При ошибке проверьте `doctor`, состояние клиента, выбранную рабочую область и права владельца ключа.
